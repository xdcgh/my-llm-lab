# 仓库接续与教学约定

建立日期：2026-09-27；本地接续协议更新：2026-10-01。仓库：`https://github.com/xdcgh/my-llm-lab`，默认分支 `main`。
本文件记录用户确认的合作方式，不声称任何聊天工具始终有权限或能力访问仓库。

## 每次接续

首选：用户回来继续时，通过 Desktop Commander Remote 列出设备，核对 `Mac-Studio.local`，
实际访问 `/Users/xudacheng/Downloads/my-llm-lab`，不按设备列表第一项猜测机器。
先读 AGENTS.md、PROGRESS.md、HANDOFF.md，按需读 ROADMAP.md；再核对 git status、HEAD、
当前手写代码、相关 runs/ 与最近学习记录。不要扫描 .venv、密钥或无关目录。

本地文件保存后即可读取，包括未 commit/push 的文件；尚未保存的编辑器缓冲区不保证可见。
不要求用户为了继续学习先 push。GitHub 用于版本备份和本地连接不可用时的后备读取；
远端路径只包含已 push 的提交，归档只包含归档版本。不得混淆三者的证据范围。
只报告实际读取的本地提交与文件；没有 fetch 就不能把 origin/main 缓存说成远端最新状态。

本轮用户授权通过插件同步学习记录。每轮结束，可针对当轮已核对证据小范围更新
PROGRESS.md、HANDOFF.md 与 notes/learning_sessions/；教学约定有变化时再同步 AGENTS.md。
不代写用户的练习、不擅自改课程代码或依赖；运行实验遵循用户当轮请求。
写入前校验当前内容并备份，写入后回读；保留用户已有改动，遇冲突停下核对。
仅当用户明确要求时才 commit/push、安装下载或执行长任务；不自动执行 git pull、reset 或覆盖工作区。

连接或权限失效时说明具体失败，再使用公开仓库或用户提供的快照。
读取和同步只在处理当前对话时进行，不是后台监控，不承诺新聊天自动加载。
新聊天可只给项目路径和“通过插件按 HANDOFF.md 接续”，前提是工具可用、设备在线且已授权。
项目文件是可重新读取的学习存档，不会扩大模型上下文窗口，也不能改变工具权限。

## 教学方式

每次只推进一个小问题。先写短代码，再解释输入、输出、形状、设备、dtype、参数及梯度。
数学表达首次出现时，说明：怎么读、每个符号表示什么、为何这样写、如何对应代码。
有可核实的英文全称就提供；是惯例就说惯例；词源无法确认时，不编造英文缩写或历史故事。
区分“真实词源”“帮助记忆的关联”和“目前约定”。不将英语背景视为已经懂数学的前提。

“助手讲过”“程序跑通”“用户明确理解”是三个独立状态。不能自动把前两者当作第三者。
先使用 CPU/FP32 验证小例子，再讨论 MPS 和性能。环境管理使用 uv，不更改全局 Python。

## 更新与验收

新功能以短课程文件为主，不直接覆盖用户笔记。修改已有内容时，需要基于实际版本生成
可预览差异、校验原内容、保留备份；不按未经核对的行号盲目替换。
插件可用时，助手可在上述授权范围内实际同步本地记录；否则提供用户执行的补丁。
无论哪种方式，都不冒称已修改 GitHub，不自动 commit、push、上传数据或启动后台任务。

`PROGRESS.md` 记录当前阶段及未理解的问题；按时间保留学习日志，不靠覆盖旧记录“清空历史”。
每次运行产生实验记录，但不得自动更新为“理解通过”。如果旧进度与新记录矛盾，先核对证据。

## 工具无法读远端时

在项目根目录执行：

```bash
git archive --format=zip --output=../my-llm-lab-snapshot.zip HEAD
```

上传前核对已跟踪内容，不包含密钥、真实工单和客户数据。只因 `.gitignore` 有排除规则，
不能保证已经跟踪过的敏感文件被排除。归档不包含 `.git` 历史及未提交文件；可另附
`git rev-parse HEAD` 的结果，方便定位版本。
